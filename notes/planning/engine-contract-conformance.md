# Engine contract conformance baseline

This is the baseline for flat-list item 1. It records established behavior rather than redefining the engine. The focused checks are `tests/engine_contract.rs` and `tests/test_engine_contract.py`; broader CRUD coverage remains in `tests/modules/test_graph_core.py` and existing Rust tests.

| Established rule | Rust | Python |
| --- | --- | --- |
| An empty graph is a valid construction state. | `Graph::new()` | `Graph()` |
| Graphs default to undirected; direction is selected at creation. | `Graph::new_with_type(GraphType::Directed)` | `Graph(directed=True)` |
| One active node with no edges is the smallest meaningful graph. | `add_node`, membership, count, empty neighbors and degree | `add_node`, membership and counts |
| A newly created ordinary node has `entity_type = "base"`. | Typed attribute read | Python attribute read |

These rules are checked in both languages. They do not assert that every current view or historical read is already immutable.

Known contract gaps assigned to later items:

- Python `add_node(node_id=...)` now rejects unsupported custom numeric IDs before allocating. Caller-controlled identity uses the managed external-ID API from item 6.
- `Subgraph` pins IDs but reads live parent values; immutable state-pinned views belong to item 26.
- Timestamp snapshots select commit timestamps, not effective-time graph states; temporal reconstruction belongs to items 17–18 of the flat list.
- Direct mutations still require the legacy manual `commit`; routing them through automatically published versions belongs to item 9.

Item 2 live-state audit: `Graph` is the checked read boundary for node and edge attributes and topology. Node/edge entity handles now use it rather than querying retained pool slots directly. An inactive ID returns an error for entity-specific reads and is absent from active ID collections; bulk attribute-column reads retain their established aligned `None` result for inactive IDs. The focused checks are `tests/active_state_contract.rs` and `tests/test_active_state_contract.py`. Raw `GraphPool` access is a low-level storage API, not a live graph view. Algorithm-specific state and direction behavior remains under items 3 and 28.

Item 3 direction audit: Directed edge lookup and filtering, BFS/DFS, shortest path, all paths, and graph adjacency matrices now follow stored edge orientation. The pathfinding algorithm CSR cache uses the backing graph's direction; undirected paths retain reverse traversal. Focused checks are `tests/directed_contract.rs` and `tests/test_directed_contract.py`. Distinct weak/strong component definitions and algorithm-specific directed variants remain in item 28; stable path edge selection among parallel edges remains in item 4.

Item 4 edge identity audit: Parallel edges and self-loops have separate stable edge IDs. Shortest path now retains the chosen edge ID and its actual path weight; all simple paths enumerate parallel edge instances separately. Recorded snapshots preserve both parallel edge IDs and their typed values. Focused checks are `tests/edge_identity_contract.rs` and `tests/test_edge_identity_contract.py`. The proposed explicit endpoint-rewiring mutation is a separate history/change operation in item 13.

Item 5 mutation validation: Node/edge creation parses properties before allocating IDs. Rust `add_nodes_with_attrs` rejects system-managed node properties before allocation and retains columnar writes. Bulk node/edge removal validates active membership and duplicates for the whole input before changing topology. Python bulk setters collect conversion errors across entries and columns before calling Rust. Focused checks are `tests/mutation_validation.rs` and `tests/test_mutation_validation.py`, alongside the existing bulk-attribute checks. Duplicate removals now raise `InvalidInput`/`ValueError` before any write; missing or non-string `uid_key` values also reject node creation before allocation. Read-only Rust preflight checks let Python combine conversion and semantic errors in the same rejected call. Original input positions are retained even when an earlier ID cannot be decoded. Structurally malformed rows or columns report their structural error; fields that cannot be decoded cannot receive semantic validation. This establishes rejection atomicity for these input classes, not crash recovery or automatic version publication.

Item 6 external identity: `external_id` is a system-managed text property. `NodeUpsert`/`EdgeUpsert` and their Python row APIs validate the complete input before allocation or writes, preserve missing properties, and make identical repeated payloads a no-op. One indexed namespace covers nodes and edges across groups and retained branches in a graph instance. Empty IDs, duplicate input IDs, cross-kind collisions, reserved properties, inactive/renamed reservations, and conflicting edge endpoints reject the operation. IDs are opaque case-sensitive strings; UUID normalization belongs to the adapter. Directed edges require the same ordered endpoints; undirected edges accept reversed input without rewiring. Active lookup checks the current property and optional `group_id`; allocation lookup can identify inactive entities and old names. Aliases remain reserved through rename, removal, branch switching and reset until explicit future purge. Snapshot lookup uses pinned properties; materializing a snapshot as a new independent graph rebuilds only that snapshot's bindings.

Focused checks are `tests/external_identity.rs` and `tests/test_external_identity.py`. Reserved identity writes are rejected through scalar, bulk, column, batch, and subgraph entry points before mutation. Subgraph bulk writers now use checked Graph writers and record property deltas. Existing JSON export/import preserves current identity text, active numeric IDs and endpoints regardless of file order, including sparse IDs. It does not preserve complete history, inactive reservations, or discarded-ID high-water counters; those remain item 10. Ordinary `uid_key` creation rejects duplicate mappings; ambiguous text lookup and forward Python mappings raise errors instead of selecting an arbitrary node.

Item 7 property-value bridge: one fallible converter serves Python constructors, graph reads, columns and table cells. Existing binary values return bytes, homogeneous sequences retain element type, and structured JSON values return decoded containers. Explicit vector factories disambiguate empty vectors. Conversion rejects integer overflow, unsupported objects, non-string structured keys, cycles and excessive nesting before public creation writes. Returned Python containers are copies. Snapshot property reads distinguish missing (`None`) from present null (`AttrValue` containing `None`); ordinary columns retain their existing null/missing projection.

Core equality, total ordering and hashing now agree for collections, entity references and optimized storage forms. NaNs share property identity; signed zeros share identity. Compression uses explicit little-endian float encoding, safe byte decoding and size validation. Focused checks: `tests/property_values.rs` and `tests/test_property_values.py`. Current scalar/vector floating properties remain f32, integers i64; native dates/times and full pool/history persistence remain open. Snapshot referent reconstruction is separate from storing an opaque reference value. General subgraphs still read live parent properties (item 26).

For each subsequent item, add focused Rust and Python conformance checks for the behavior being changed, then update this baseline when the contract or a documented gap changes.

Item 7 typed export repair: graph JSON export version 2 uses stable logical type tags and raw f32 bit patterns. Active inline properties round-trip without skipping nulls, bytes, vectors, structured values or entity-ID arrays. Invalid properties and unsupported pooled references fail before opening the destination. Loader rejects invalid versions/tags/payloads, duplicate numeric IDs and absent edge endpoints; legacy scalar documents remain readable. Python now exposes the same Rust save/load boundary with path-like inputs. Focused tests: `tests/property_persistence.rs`, `tests/test_property_persistence.py`. Export does not contain history, inactive IDs, retained aliases, counters, stored subgraphs, indexes or full configuration. Atomic file replacement and durable full-engine recovery remain item 10.

Item 8 semantic kinds: checked node `labels` assignments require distinct nonblank names and canonicalize sorting; edge `relationship_type` accepts nonblank text or explicit null. Helpers retain base/meta identity and parallel edge IDs. Core preflight covers new rows, scalar/bulk/column writers, upserts and mixed batches; rejected input preserves allocation, properties and dirty state. Repeated unsorted-label upserts remain idempotent. Snapshot and typed-export tests verify prior values and restored applicability. `GraphSchema` audits active entities for required, nullable and logical type rules across all matching labels/types without changing state. This is explicit auditing, not installed write enforcement. Focused checks: `tests/kinds_schema.rs`, `tests/test_kinds_schema.py`. Item 9 owns proposed-state enforcement and compatible checked creation; schema policy history, ontology migration and indexes remain open.

Item 9 schema-controlled publication: Rust `apply_batch_with_schema` / Python `apply_batch(schema=...)` validate a read-only proposed-state overlay before graph mutation. New/staged labels and values are read together; unchanged survivors are checked; explicit removals and implicitly removed incident edges are excluded. Required system defaults are visible for new nodes. Rejection preserves current state, history, properties, tracking and ID high-water counters. Success publishes one state with older snapshots unchanged. Policy is per call, not installed on direct writers. Focused checks: `tests/batch_schema.rs`, `tests/test_batch_schema.py`. Direct-write migration, effective-time metadata, installed schema policies and durable publication remain open.


Item 9 checked publication and item 10 journal: the checked writer now coordinates mixed identities, scalar/bulk values, schema validation and per-change signed-microsecond times before publication. DurableGraph adds installed schema revisions, an exclusive file lock, synced CBOR frames, stable replay clocks/hashes, retained branch allocation/identity state and explicit indeterminate-failure handling. Graph::pool_mut requires an exclusive borrow so immutable durable reads cannot bypass the journal. Tests: tests/durable_journal.rs, src/storage/journal.rs failure-injection tests, tests/test_durable_graph.py, plus publishing_writer/publication_times/batch_identity suites. Item 9's documented checked operations have a durable boundary; legacy Graph manual calls do not inherit it. Item 10 remains incomplete for pooled/meta contents, import, checkpoints, compaction and migrations. See docs/api/durable-storage.md for bounded record size, full replay cost and current GIL/concurrency limits.

Item 10 full-journal backup: DurableGraph.backup verifies a synced temporary copy before no-overwrite publication and directory sync. Rust/Python checks cover retained branches/history, independent later writes, existing destinations, corrupt input and temporary cleanup. Restore uses DurableGraph.open. This copies the full operation log; checkpoint/compaction and pooled content remain open.

Items 10/12 retained selections: deactivation preserves stored membership, state switches/reset retain the pool and historical column indices/endpoints, and missing meta referents reject before allocation. Detached snapshots reject unresolved pooled references. Strict/lenient collapse preserves base/meta identities and honors extract/collapse node strategy. Tests: tests/retained_subgraphs.rs and tests/test_retained_subgraphs.py. Expanded live-parent properties, portable referents and durable meta storage remain open; repeated-switch property-column reuse is not yet implemented.

Item 29 identity/statistics: eye produces diagonal identity; checked identity uses the underlying fallible constructor.
