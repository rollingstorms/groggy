## [Unreleased]

### Preparing 0.6.0

- Checked automatic Python mutation publication, explicit effective-time deltas,
  immutable read defaults, pinned table/query identity and tracked restoration.
- Retained archives, journal recovery, explicit checkpoints and retention tools,
  within the documented storage and platform boundaries.
- Consolidated matrix/numeric foundations, f64 property defaults and expanded
  graph/numerical algorithms; broader conformance and scale work remains open.
- Classic BFS, DFS, Dijkstra and A* now consume pending selected topology and
  values through shared native read frames, preserving one outer acceptance.
- Selected retained lifecycle/window helpers now follow surviving pending IDs
  after topology changes; provisional IDs remain guarded against invented history.
- Accepted snapshot acquisition and node/edge retained diffs now compose after
  pending topology while keeping unpublished working state separate from history.
- Fixed child frames validate every node/edge attachment target before staging,
  publication or transient output, including full-owner history diff maps.
- Pending child captures share one accepted base and prepared topology, copy only
  frame values and revalidate changed targets, reducing measured repeated allocation.
- Pending subgraph producers and certified for-each bodies now use exact child
  selections, shared nested parsing and execution, and immutable emitted sources.
- Long atomic runs reclaim expired weak capture metadata and oversized registry
  capacity while preserving live earlier table attachment authority.
- Temporal value decay now accepts pending selected nodes/edges and ordered
  columns, preserving explicit input identity and one atomic acceptance.
- Flow-map update/residual primitives now use checked integer/finite arithmetic
  and compose with pending topology without rebinding explicit map IDs.
- Filters/order, numerical maps, fused/community primitives and sampling masks
  now compose after pending topology through shared selected readers.
- Typed immutable pipeline inputs, staged topology creation/revision/removal and
  13 captured algorithm-table kernels in local and outer atomic programs. Shared
  creation IDs, effect-order preflight, exact final selections and late rollback
  preserve one accepted mutation across builders. Certified property loads,
  initialization, arithmetic and attachments now use the pending selected state
  after topology, including provisional IDs and property reloads. Structural,
  neighbor, expression-transform and path readers now share that selected source.
  Explicit captured-table attachments preserve row identity, optional effective
  times and one acceptance, with weak capture authority and strict alias checks.
  Certified compute loops and message-passing blocks refresh pending reads and
  retain typed loop bindings through the shared native executor. General topology loops and
  unadapted effects remain open.
- Explicit storage platform capabilities, Windows locked-handle verification,
  compatible schema migration examples and independent finite graph references.
- Measured archive validation allocation reductions and contiguous dense-product
  access with preserved checked arithmetic; broad memory/throughput targets remain open.
- Cargo-derived distribution/runtime version, standard Maturin builds without
  build-time extension introspection, packaged stubs/typing marker, and working
  public native display helper exports.
- Executable embedded-core acceptance workflow across graph, table, numerical,
  temporal and recovery APIs.
- Artifact-backed Python/docs and ownership gates, locked source-distribution
  rebuild verification, SHA256 qualification receipts and publication gated by
  native/platform checks. Manual artifact qualification cannot publish.
- Package interpreter range `>=3.8,<3.13` matches the current PyO3 build limit;
  the nested build no longer forces experimental forward compatibility.
- Creator-checked Arc/OwnerCell handles permit safe native finalization on any
  thread, fixing writable Graph/connected-wrapper cyclic-GC destruction errors.
  Durable GC releases file locks without owner polling; foreign live access still
  rejects. Native attribute collections and matrix-view metadata retain their
  backing owners. Explicit Rust handle types and custom temporal strategy bounds
  have migration changes documented in the owner-lifetime guide.

This is an unreleased development version. See [0.6.0 scope and migration
notes](RELEASE_NOTES_0.6.0.md) and [release qualification](RELEASE_STATUS.md).
The writable-owner cyclic finalization defect is fixed within the documented
thread-access boundary.

## [0.5.2] - 2024-12-04

### Added
- **Batch Executor**: 10-100x performance improvement for iterative algorithms
  - Automatic loop optimization with `builder.iterate()`
  - Structured loop representation for future JIT compilation
  - Graceful fallback for unsupported operations
- **Native Algorithms Module** (`groggy.algorithms`):
  - Centrality: `pagerank()`, `betweenness()`, `closeness()`
  - Community: `lpa()`, `louvain()`, `leiden()`, `connected_components()`
  - Pathfinding: `bfs()`, `dfs()`, `dijkstra()`, `astar()`
- Complete Builder DSL documentation with tutorials
- Algorithm documentation for all 11 native algorithms

### Fixed
- Histogram IR conversion preserving source field
- Node degrees test for directed graphs
- Loop variable slot allocation for multi-iteration algorithms
- 16 test failures → 100% test coverage (46/46 passing)
- PageRank builder implementation matches native semantics
- Core encoder support for `core.load_attr`

### Improved
- Builder DSL algorithm validation and correctness
- IR optimization pipeline with structured loops
- Step encoding for all builder operations
- Test suite coverage and reliability
- Documentation structure and navigation

### Changed
- `init_scalar` → `core.constant` (naming consistency)
- `load_edge_attr` → `graph.load_edge_attr` (namespace clarity)

### Known Issues
- PageRank: ~5-6% numerical drift after 100+ iterations
  - Algorithm is mathematically correct for practical use (10-20 iterations)
  - Will add per-iteration normalization in future release if requested

### Performance
- PageRank (1000 nodes, 100 iterations): 100x faster with batch executor
- LPA (10000 nodes): 40x faster with batch executor
- Algorithms using `builder.iterate()` automatically benefit

### Documentation
- Complete algorithms guide with all 11 algorithms
- Builder DSL guide with batch executor deep dive
- Native vs Builder decision guide
- 4 tutorials (Hello World, PageRank, LPA, Custom Metrics)
- API reference for all components

This release represents a fundamental transformation of Groggy from a graph library into a comprehensive graph analytics platform with visualization, the foundation for neural networks, and graph<->table operations.

### 🚀 Upgrade Guide

#### From v0.4.0

Most existing code will work without changes:

```python
import groggy as gr

# Existing code continues to work
g = gr.Graph()
g.add_node("alice", age=30)
g.add_edge("alice", "bob", weight=0.8)
subgraph = g.connected_components()[0]
```

**New capabilities available**:

```python
# Visualization
g.viz.show()  # Interactive visualization in Jupyter
g.viz.save("graph.html")  # Export to standalone HTML

# Type stubs for IDE autocomplete
g.nodes.  # <-- Full autocomplete available!

# Advanced table operations
table = g.nodes.table()
grouped = table.groupby("department").agg({"age": "mean"})
table.to_csv("nodes.csv")

# Matrix operations with auto-diff
import groggy.neural as gn
matrix = g.adjacency_matrix()
activation = gn.relu(matrix)
gradient = activation.backward()

# Meta-API discovery
from groggy.imports import discover_api
api_graph = discover_api(gr.Graph)
```
